# Case study: `astral-sh/uv`

> Marketing/positioning writeup at https://alint.org/examples/astral-sh-uv/. This README is the engineering reference: tooling inventory, mapping, gap catalogue, validation status.

Inventory of the structural-validation tooling in `astral-sh/uv` and an alint
config that replaces the rules alint can express today, plus a catalogue of the
rules that need new alint primitives.

**Repo state captured:** 2026-05-03, sparse-clone of
`astral-sh/uv` HEAD at the time of the inventory.

---

## Summary

uv ships **~20 distinct structural-validation surfaces** — 8 GitHub Actions
`check-*.yml` workflows, ~15 Python helper scripts under `scripts/`, plus
manifest-shape conventions enforced informally by code review (e.g. "every
`crates/uv-*` opts into `[workspace.lints]`"). About **40 % map directly to
existing alint rules**, **30 % need new alint primitives** (codegen drift
detection, cross-lockfile equality, built-wheel manifest comparison), and
**30 % are out of alint's scope** (the build-system, dist-plan, and Python
wheel-content checks alint deliberately doesn't try to do).

The 40 % that *do* fit translate cleanly to a 13-rule alint config (below)
plus 6 `command` rules that shell out to `shellcheck`, `ruff`, `typos`,
`cargo-shear`, `cargo fmt`, and `cargo clippy`. uv's convention pattern across
its 67 published crates (`[lints] workspace = true` + `edition.workspace = true`
+ `license.workspace = true`) is enforced nowhere in CI today —
violations would only surface on the next `cargo metadata` run by a
contributor. The alint rule `uv-crate-inherits-workspace-lints` collapses the
67-crate convention check to one declarative rule. Same shape for
`uv-crate-edition-from-workspace` / `uv-crate-license-from-workspace`. All
three flag exactly the documented-as-exceptional crates (uv-trampoline,
uv-performance-memory-allocator, uv-pep440, uv-pep508).

## Existing tooling inventory

### Maps to existing alint rules (drop-in replacements)

| Source | What it checks | alint replacement |
|---|---|---|
| `.github/workflows/check-fmt.yml` (rust step) | `cargo fmt --all --check` | `command` rule on root `Cargo.toml` |

| `.github/workflows/check-fmt.yml` (prettier step) | `npx prettier --check .` | `command` rule (omitted; alint's `final_newline` + `no_trailing_whitespace` already cover the most common Prettier complaints, so the bundled `oss-baseline` covers it transitively) |
| `.github/workflows/check-lint.yml` (ruff) | `uvx ruff check .` | `command` rule per `*.py` |
| `.github/workflows/check-lint.yml` (shellcheck) | `find . -name '*.sh' \| xargs shellcheck` | `command` rule on `**/*.sh` |
| `.github/workflows/check-lint.yml` (typos) | `crate-ci/typos` action | `command` rule on `_typos.toml` |
| `.github/workflows/check-lint.yml` (clippy) | `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings` | `command` rule on root `Cargo.toml` |
| `.github/workflows/check-lint.yml` (cargo-shear) | `cargo shear --deny-warnings` | `command` rule on root `Cargo.toml` |
| `.github/workflows/check-zizmor.yml` (action pinning subset) | Pin actions to commit SHAs | `gha-pin-actions-to-sha` from `bundled/ci/github-actions@v1` (subset — zizmor catches more) |
| Implicit convention: every `crates/uv-*` declares `[lints] workspace = true` | 67 of 69 do; the 2 exceptions are documented | `for_each_dir` + `file_content_matches` (regex on the manifest body) — **highest-leverage rule of the whole config** |
| Implicit convention: every `crates/uv-*` inherits `edition` / `license` from `[workspace.package]` | All except uv-pep440/508 (different license) and uv-trampoline (excluded from workspace) | Two `for_each_dir` rules with regex on inheritance form (`{ workspace = true }` OR `.workspace = true`) |
| Implicit convention: every `crates/uv-*` has a `README.md` | All 67 published crates do (auto-generated by `scripts/generate-crate-readmes.py`) | `for_each_dir` + `file_exists` |

13 declarative rules + 6 `command` rules — direct replacements covering
~16 of ~20 distinct check surfaces.

### Needs new alint primitive

| Source | What it checks | What alint needs |
|---|---|---|
| `scripts/check-trampoline-version-consistency.py` | The `windows` crate version in `Cargo.lock` matches the same key in `crates/uv-trampoline/Cargo.lock` | A `cross_file_field_equals` rule kind: pull a JSONPath value from file A, compare to a JSONPath value from file B, fail if they differ. **Generalised use case:** any monorepo with vendored / split workspaces that needs to keep dep versions in sync. |
| `scripts/check_uv_wheel_contents.py` | Built `*.whl` archive contains exactly a known set of file names (with `VERSION` substitution) | An `archive_contents_matches` rule kind: open `*.{whl,tar.gz,zip}`, list members, compare against an expected set with template substitution. Narrower use case (only repos that publish wheels), but applies to every Python package on PyPI. |
| `.github/workflows/check-generated-files.yml` (`cargo dev generate-all --mode dry-run`) | A set of generated files (CLI reference, options reference, env-vars reference, sysconfig metadata) match what their generator would re-emit today | A `command` rule technically works (uv already does this with `--mode dry-run`), but it's repo-specific. A reusable `generated_file_fresh` rule that runs a generator and diffs the output against the on-disk file would be the principled primitive. Alint's deliberate non-goal: running codegen. So leave on `cargo dev`. |
| `.github/workflows/check-generated-files.yml` (`cargo dev generate-json-schema --mode check`) | `uv.schema.json` matches the generator's output | Same as above. |
| `.github/workflows/check-lint.yml` (`validate-pyproject`) | `pyproject.toml` validates against the PEP 621 + tool-specific JSON schemas | `json_schema_passes` exists, but resolving "the PEP 621 schema" is a published-schema lookup. Could ship a bundled `python/pep-621-shape@v1` ruleset that hardcodes the schema URL. Promising follow-up — **strong v0.10 candidate**. |
| `.github/workflows/check-lint.yml` (`cargo-deny bans` for uv-build) | License + dependency policy | `cargo-deny` is the canonical tool; alint's `command` rule wraps it. Nothing to invent. |
| `.github/workflows/check-zizmor.yml` (full SAST) | Beyond pin-to-SHA: GHA expression-injection patterns, dangerous defaults, etc. | zizmor is a static-analysis tool that does AST-level pattern matching on workflows. Alint's deliberate non-goal: AST pattern matching. Keep zizmor. |

**Gap pattern: cross-file equality / templated comparison.** uv has two
scripts (`check-trampoline-version-consistency.py`,
`check_uv_wheel_contents.py`) that are variants of "value at point X in
file A must equal value at point Y in file B (possibly with template
substitution)". This generalises into a `cross_file_field_equals` rule kind
and shows up in many monorepos that maintain split workspaces or publish
multi-format artefacts. Worth a v0.10+ design pass.

### Out of alint's scope (use the existing tool)

These are codegen / build-system / archive-content checks. Alint's non-goals
are deliberate; the case study notes them as "alint doesn't try to do this;
keep your existing script."

- `cargo dev generate-all`, `cargo dev generate-json-schema`,
  `cargo dev generate-sysconfig-metadata` — codegen drift; out of scope
  (alint doesn't run codegen)
- `cargo publish --workspace --dry-run` — build-system check; out of scope
- `dist plan --output-format=json` — release-system check; out of scope
- `mkdocs build --strict` — docs build; out of scope
- `cargo dev generate-cli-reference`, `cargo dev generate-options-reference`,
  `cargo dev generate-env-vars-reference` — codegen drift; out of scope
- `scripts/check_registry.py`, `scripts/check_system_python.py`,
  `scripts/check_embedded_python.py`, `scripts/check_cache_compat.py` —
  runtime integration tests, not structural validation
- `scripts/registries-test.py`, `scripts/check_uv_wheel_contents.py` —
  runtime / archive-content tests
- `scripts/repair-sdist-cargo-lock.py`,
  `scripts/patch-dist-manifest-checksums.py` — release artefact patching;
  out of scope

### Already covered by other linters uv uses

- `cargo clippy`, `cargo fmt` — Rust toolchain; alint wraps via `command`
- `ruff check`, `ruff format` — Python toolchain; alint wraps via `command`
- `typos` — spelling; alint wraps via `command`
- `shellcheck` — shell linter; alint wraps via `command`
- `cargo shear` — unused-deps detector; alint wraps via `command`
- `zizmor` — GHA SAST; keep as a separate workflow
- `validate-pyproject` — PEP 621 schema validator; keep as a separate
  workflow until the bundled `python/pep-621-shape@v1` ruleset lands

## Starter alint config (drop-in)

[`/.alint.yml`](.alint.yml) in this directory. Replaces ~16 of ~20 check
surfaces. The remaining 4:

- 2 need new alint primitives (cross-file equality + archive-content) — file
  as v0.10+ feature requests
- 4 are explicitly out of alint's scope (codegen drift, build-system,
  release-system) — keep the existing scripts

The 13 declarative rules cover:

1. **Per-crate manifest hygiene (3 rules):** every `crates/uv-*` opts into
   `[workspace.lints]`, inherits edition + license from the workspace.
   These three rules collectively replace what's currently a "code review
   catches it" practice — no automated check fires today.
2. **Per-crate convention (1 rule):** every `crates/uv-*` has a README.md.
   Currently enforced only via `scripts/generate-crate-readmes.py`'s
   side-effect of overwriting any missing README; a missing crate dir is
   silently skipped.
3. **Workspace-root manifest (3 rules):** `resolver` declared, workspace
   edition pinned, MSRV pinned.
4. **Toolchain / dist policy (1 rule):** `rust-toolchain.toml` pins a
   specific compiler version.
5. **Python distribution (2 rules):** `pyproject.toml` declares
   `build-backend = "maturin"` and lists both license files.
6. **License files (2 rules):** both `LICENSE-APACHE` and `LICENSE-MIT`
   exist (uv's dual-license commitment, stricter than oss-baseline).
7. **Bundled rulesets contribute additional 30+ rules** for free:
   OSS-baseline hygiene, Rust source conventions, Python source
   conventions, CI/GHA hardening, no-tracked-artifacts, monorepo
   conventions, cargo-workspace conventions.

When run against the actual uv tree (with the bundled rulesets in scope),
**63 declarative rules pass cleanly and 9 rules surface real findings**:

- 2 violations of `uv-crate-inherits-workspace-lints` — both legitimate
  (uv-trampoline + uv-performance-memory-allocator)
- 1 violation of `uv-crate-edition-from-workspace` — uv-trampoline (no
  workspace inheritance, only crate excluded from `[workspace] members`)
- 3 violations of `uv-crate-license-from-workspace` — uv-pep440, uv-pep508
  (different license — Apache-2.0 OR BSD-2-Clause), uv-trampoline
- 3 violations of `hygiene-no-python-cache` — `.ruff_cache/` directories
  that **shouldn't be there but were committed** (a real find!)
- 2 violations of `rust-sources-snake-case` — `uv-trampoline-console.rs`
  and `uv-trampoline-gui.rs` (the two binary entry-points use kebab-case;
  Cargo allows this for `[[bin]]` targets but the convention check fires)

Every one of these 9 findings is either a documented exception (which the
rule's `select:` could be tightened to skip) or — in the case of the
3 `.ruff_cache/` finds — a real hygiene bug that no current uv check
catches.

## Performance comparison (placeholder — bench when validation pass scales)

uv's CI shellouts run sequentially within each workflow step. The
non-clippy structural checks (fmt, ruff, shellcheck, typos, pep-621
validation, generated-files dry-run) collectively take 2-3 minutes
walltime per PR.

alint's bundled rules run in parallel via the v0.9.3 dispatch flip + the
v0.9.5+ cross-file fast paths. Expected: ~0.5 s for the alint-replaceable
declarative subset on a uv-scale repo (~6k Rust source files; the v0.9.6
S9 polyglot bench at 100k files lands at 1.13 s, and uv is ~10× smaller).

To benchmark for real: run the uv `check-fmt` + `check-lint` workflows
locally, then run `time alint check`. Deferred to the per-repo measurement
pass.

## Followup feature work surfaced

- **`cross_file_field_equals` rule kind** — covers the trampoline
  cross-lockfile sync check; same primitive shows up in every monorepo
  with split workspaces or vendored packages. Now absorbed into the
  broader `cross_file_value_equals` v0.10 ship-target.
- **`python/pep-621-shape@v1` bundled ruleset** — wraps the published
  PEP 621 + tool.* schemas, replaces the `validate-pyproject` shell-out
  in CI for any Python project. Formal v0.10 design candidate.
- **`archive_contents_matches` rule kind** — narrower (built-wheel
  shapes); every Python package on PyPI could use it. Remains a
  uv-unique candidate.

Surface coverage: 16/20 (80%) of uv's structural checks moved to declarative
config. The 20 % that don't move are deliberately out of scope (codegen,
build, release artefact patching).

## Future analysis

Concrete analyses to follow up with on the live tree:

- **`alint suggest` against the live `astral-sh/uv` tree** — capture which
  bundled rulesets the heuristic auto-detects (expect at minimum
  `oss-baseline@v1`, `python@v1`, and likely `rust@v1` given the polyglot
  shape), and compare against the rulesets manually adopted in this config.
  Will surface any unintentional ruleset omissions.
- **JSON-output slow-rule scan** — run
  `alint check --format json --config .alint.yml /tmp/uv` and bucket the
  per-rule wall-times to identify the heaviest `command:` shellouts; the
  ruff/clippy/cargo-shear shellouts dominate today and are candidates for
  consolidation under a `command_idempotent` v0.10 rule kind once it lands.
- **Per-crate `nested_configs: true` opportunity** — uv's 67 published
  crates each ship their own `Cargo.toml`; a per-crate `.alint.yml` could
  carry crate-specific overrides (e.g. `uv-trampoline`'s exception from
  `[lints] workspace = true`) without polluting the workspace-root config.

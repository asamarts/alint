# alint plugin contract (WIT draft)

`alint-plugin/v0.1/plugin.wit` is the draft `alint:plugin@0.1.0` contract:
shared std-only types, an `adapter` world, and an `analyzer` world. Inputs are
host-pushed; there are no host callbacks, resources, handles, or recursive
types in this version. `wire.lock` is the append-only protobuf wire-number map
generated by witforge.

The WIT is the source of truth for the contract. The hand-written traits in
`alint_core::plugin_api` remain the executable v0.21 contract until the
generated `alint-plugin-api` crate replaces them (slice P2). Until then, the
tests in `crates/alint-witforge-consumer` convert every `plugin_api` type and
trait to and from the generated code and account for every item on both
sides, and `ci/scripts/witforge-consumer.sh` checks the generated code against
the WIT, so a change to either side must update the other in the same pull
request.

## Status: draft

0.1 is a draft with no compatibility promise and may still change in place.
The first alint release that loads plugins freezes it: that release adds
`alint-plugin/released`, after which a released version never changes and
changes ship as a new minor version
([ADR-0027](../docs/adr/0027-plugin-contract-0-1-stays-a-draft.md),
`docs/design/plugin-architecture.md` section 8.3).

## Checking and regenerating

`crates/alint-witforge-consumer` holds witforge's output for this contract:
the plain Rust types and traits (`src/plain`), the protobuf schema
(`proto/v0.proto`), and the glue between them (`src/glue`). Its `build.rs`
generates the prost and proto3-JSON code from the schema, so none of that is
committed. The committed files are witforge's output byte for byte, which is
why `src/lib.rs` keeps them out of rustfmt with `#[rustfmt::skip]`.

Check the contract and the committed output with the pinned witforge release:

```sh
ci/scripts/witforge-consumer.sh            # witforge on PATH
WITFORGE_BIN=/path/to/witforge ci/scripts/witforge-consumer.sh
```

After changing `plugin.wit` (and its `wire.lock`, with `witforge lock`),
regenerate the committed output instead of editing it:

```sh
ci/scripts/witforge-consumer.sh --write
```

`ci/scripts/test-witforge-consumer.sh` runs the check's controls: the
unmodified tree must pass; a changed, extra, or missing generated file, an
unlocked member, or a version directory the script does not check must fail;
and `--write` must restore a changed file. Without witforge the controls skip
(exit 77, which `ci/scripts/shell-tests.sh` reports as skipped), unless
`WITFORGE_REQUIRED=1`.

# Design doc: architecture diagrams as code (Phase 4 / WS3)

Status: Implemented (`xtask gen-arch` + committed `crate-graph.md` + `workspace.dsl`, Phase 4).
Decisions: ADR-0001 (spec-driven development). WS3 of `spec-driven-development.md`.
Demand evidence: the hand-drawn ASCII crate tree in `ARCHITECTURE.md` is the only
structural picture today; it lists directories, not the dependency graph, and is
maintained by hand. There is no machine-checkable record that, e.g., `alint-core`
stays dependency-free or that the workspace stays acyclic.

## 1. Problem

A linter whose pitch is "stop documentation drifting from reality" should not
have an architecture picture that drifts. WS3 wants two things the prose
`ARCHITECTURE.md` can't give:

1. A **code-extracted** structural diagram that regenerates from the source of
   truth (`cargo metadata`) and so cannot lie about the crate graph.
2. A **hand-modeled** C4 intent model that says *why* the containers exist —
   kept honest by a gate so it can't silently omit a crate.

Without it, the crate graph is an ASCII tree someone updates (or forgets to);
"core has no internal dependencies" is a convention with nothing enforcing it;
and a new crate can land with no diagram noticing.

## 2. Surface area

Two committed artifacts under `docs/design/architecture/`, plus gates:

- **`crate-graph.md`** — generated by a new `xtask gen-arch [--check]`
  (mirroring `gen-schema`/`gen-facts`). Contains a Mermaid graph of the
  workspace's intra-workspace dependency edges (renders natively on GitHub and
  alint.org — no Graphviz/SVG toolchain) plus a crate table (name, role from the
  crate's `description`, dependency tier). Whole-file content-diff gated.
- **`workspace.dsl`** — a hand-written Structurizr C4 model (Apache-2.0 DSL) for
  C4 levels 1-3 (System Context, Container, Component). The ten crates are
  *components*, not containers. Source of truth for the C4 intent; renders via
  the consolidated `structurizr` tool offline (not required in CI). Kept honest
  by the crate-name consistency gate.

`ARCHITECTURE.md` gains a short "Building block view" pointer (arc42 cherry-pick)
linking the generated graph, the C4 model, and `docs/adr/`. The live
`manifest.json` and other generators are untouched.

## 3. Semantics

`xtask gen-arch` shells out to `cargo metadata --format-version 1 --no-deps`
(offline, deterministic), keeps each workspace package's dependencies that are
themselves workspace members, and renders:

- A `graph TD` Mermaid block: one node per crate (id = name with `-`→`_`,
  label = crate name; the binary and `xtask` annotated), one edge `A --> B` per
  "A depends on B". Nodes and edges sorted for determinism.
- A table sorted by `(tier, name)`, where **tier** = longest dependency chain to
  a leaf (`alint-core` = 0). The role text is the crate's Cargo `description`.

`gen-arch` (no flag) rewrites `crate-graph.md`; `gen-arch --check` regenerates
in-memory, content-diffs the committed file, **and** verifies the C4 model:

- **Crate-name consistency:** the crate identifiers declared in `workspace.dsl`
  equal the `cargo metadata` workspace-member set. A crate added or removed
  without updating the model fails here — this is what keeps the hand layer
  honest.

Two further invariants are unit tests (not freshness, so not in `--check`):

- **Acyclic:** the intra-workspace graph is a DAG (DFS cycle check). Cargo
  already forbids cycles; the test documents the invariant and guards the
  extraction logic.
- **Layering:** `alint-core` has zero intra-workspace dependencies — the
  foundation stays a sink. (Constitution-adjacent: the engine core must not
  depend on rules/DSL/output.)

Wired into `ci/scripts/docs.sh` next to `gen-schema --check`/`gen-facts --check`;
`docs-export` copies `crate-graph.md` into the bundle for alint.org.

Dispatch class: build-time generator, like `gen-schema`/`gen-facts`/`docs-export`.

## 4. False-positive surface

N/A as an engine rule. Generator failure modes:

- **Non-determinism** across machines. Mitigated: output is names + edges only
  (no paths, no versions, no timestamps), fully sorted; `--check` would surface
  any accidental nondeterminism as drift.
- **`cargo metadata` unavailable.** It ships with cargo; absence fails loudly
  with context.
- **DSL parse brittleness** in the consistency gate. Mitigated: the gate scans
  for crate-name tokens in `component` declarations (a forgiving line scan), not
  a full DSL parse; it asserts set-equality against `cargo metadata`, so both a
  missing and an extra crate fail.

## 5. Implementation notes

New module `xtask/src/arch.rs` with `run(check: bool)`. `cargo metadata` is
invoked via `std::process::Command` and parsed with `serde_json` (already a
dep). No new dependencies; no Graphviz, no Java, no Structurizr in CI. Mermaid is
the only renderer relied on (native on GitHub + alint.org).

Deliberately **out of scope** for this pass (heavy tooling, noted as follow-ups):
`cargo-modules` per-crate internal module graphs and its `--acyclic` CI flag;
Structurizr `.war` SVG export in CI; the full arc42 12-section template (itself
drift-prone — we cherry-pick).

## 6. Tests

In `xtask` (`arch.rs` `#[cfg(test)]`):

- `gen_arch_check_passes_on_committed_tree` — `run(true)` succeeds on the
  committed `crate-graph.md` (freshness; mirrors the schema/facts tests).
- `workspace_graph_is_acyclic` — DFS cycle check over the extracted edges.
- `alint_core_is_a_dependency_sink` — `alint-core` has no intra-workspace deps.
- `workspace_dsl_components_match_cargo_metadata` — the C4 model's crate set
  equals the workspace-member set.

`ci/scripts/docs.sh` gains `gen-arch --check`; preflight inherits it.

## 7. Open questions

- **Inject into `ARCHITECTURE.md` vs standalone file?** Resolved: standalone
  generated `crate-graph.md` (clean whole-file gate like schema/facts);
  `ARCHITECTURE.md` links it rather than hosting a marker-delimited generated
  block.
- **Per-crate module graphs (`cargo-modules`)?** Deferred — needs the extra
  binary in CI for marginal value over the crate-level graph. Revisit if a crate
  grows complex enough to warrant an internal-structure picture.
- **SVG export for alint.org?** Deferred — Mermaid renders on the site already;
  add a Structurizr/`mmdc` SVG step only if the site needs static images.

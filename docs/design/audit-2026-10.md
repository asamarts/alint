# 2026-10 repository audit and remediation

Status: remediated on branch `fix/audit-2026-10` (base `ce050d28`, v0.17.0 + 43).
Targets the next minor release (0.18.0): several fixes are breaking.

## Method

Six independent review passes (core engine, rules, config layer, CLI/output/LSP,
CI/release/distribution, documentation) each had to reproduce every finding
(a failing test, or a run of the debug binary against a temp repo) before
reporting it. Every high-severity finding was then re-reproduced independently
before any fix. Each fix landed with a regression test that fails on the base
commit, and the original exploit repros were re-run against the merged binary.
Local preflight was fully green on the base commit, so every finding below was
invisible to the existing gates.

## Findings and fixes, by severity

### Critical / high (security)

| Finding | Fix |
| --- | --- |
| A template `kind: "{{vars.k}}"` expanded into a spawning kind after every spawn gate ran: arbitrary command execution from an `extends:`'d ruleset | Trust-relevant template fields (`kind`, `fix.<op>.applicability`, any `require:` depth) must be literal |
| A spawning kind nested in a template's `require:` bypassed both template gates (found during remediation) | One recursive `find_spawning_kind` shared by all three spawn gates |
| `fix: {file_remove: [safe]}` deserialized positionally into a Safe promotion that the mapping-only gates never saw; same for remote content-op demotion | Fix-op options must be a mapping |
| An untrusted rule could aim a trusted template's promoted fixer with its own `paths:` | Promotions are stripped from an effective rule with untrusted provenance |
| A remote ruleset could route `${SECRET}` into `git_commit_message` `since:`, echoed in an error | Remote bodies may not carry `${` in `since:` or `vars:` |
| XML depth pre-scan ended `<?` at the first `>`: crafted file aborted alint with a stack overflow | Pre-scan lexer matches roxmltree at every skip boundary, fails closed |
| YAML depth/alias guards bypassable via flow comments and block scalars (hang / 1.6 GB) | Pre-scan ported to libyaml's token rules |
| One NUL byte disabled `no_bidi_controls` / `no_zero_width_chars` | Both scan every file; binary findings are reported, not fixed |
| `alint baseline` / `alint init` wrote outside the repo (path or symlink) | Confined writes via temp + rename, symlinks refused |

### Medium

- `alint fix` reported "applied" (exit 0) while the violation stood.
- Unreadable in-scope files passed content rules silently (now fail closed).
- Glob metacharacters in directory names (`app/[slug]`) were pasted into globs.

- Four content rules skipped non-UTF-8 files.

## Deliberate deviations

- **XML:** no big-stack parse thread; the pre-scan is fail-closed, and a
  thread per XML file is not free.
- **Glob escaping** covers nested `paths:` and `iter.has_file` only. Nested
  `select:` / `primary:` and other options still render literally because some
  are regexes, where glob escaping would be wrong.
- **Process-group kill** is Unix-only (via the POSIX `kill` utility, since the
  workspace forbids `unsafe`); Windows gets the bounded output wait only.
- **Extended-config top-level settings** (`respect_gitignore`,
  `fix_size_limit`, `nested_configs`) stay ignored, now with a warning, rather
  than starting to apply once unset values stopped clobbering set ones.

## Open design questions

1. A remote ruleset can add `ignore: ["**"]` and silence the whole repository.
   This is the same suppression risk the loader cites for refusing `baseline:`
   from extended configs; refusing or capping `ignore:` from remotes would close
   it, at the cost of rulesets that legitimately ignore `vendor/`.
2. `when: env.X ...` lets a remote ruleset leak a secret bit by bit through
   which rules fire. Removing `env.*` from remote `when:` expressions closes it.
3. `cargo audit` / `cargo deny check advisories` are advisory-only, and release
   builds use the floating `stable` toolchain.
4. The release job moves the `v0` major tag and Docker `:latest` to whatever tag
   is being released, so a backport release would move them backwards.

# 2026-10 repository audit and remediation

Status: remediated on branch `fix/audit-2026-10` (base `ce050d28`, v0.17.0 + 43), PR #287.
Targets the next minor release (0.18.0): several fixes are breaking.

## Method

Six independent review passes (core engine, rules, config layer, CLI/output/LSP,
CI/release/distribution, documentation) each had to reproduce every finding
(a failing test, or a run of the debug binary against a temp repo) before
reporting it. Every high-severity finding was then re-reproduced independently
before any fix. Each fix landed with a regression test that fails on the base
commit, and the original exploit repros were re-run against the merged binary.
Local preflight was fully green on the base commit, so every finding below was
invisible to the existing gates.

## Findings and fixes, by severity

### Critical / high (security)

| Finding | Fix |
| --- | --- |
| A template `kind: "{{vars.k}}"` expanded into a spawning kind after every spawn gate ran: arbitrary command execution from an `extends:`'d ruleset | Trust-relevant template fields (`kind`, `fix.<op>.applicability`, any `require:` depth) must be literal |
| A spawning kind nested in a template's `require:` bypassed both template gates (found during remediation) | One recursive `find_spawning_kind` shared by all three spawn gates |
| `fix: {file_remove: [safe]}` deserialized positionally into a Safe promotion that the mapping-only gates never saw; same for remote content-op demotion | Fix-op options must be a mapping |
| An untrusted rule could aim a trusted template's promoted fixer with its own `paths:` | Promotions are stripped from an effective rule with untrusted provenance |
| A remote ruleset could route `${SECRET}` into `git_commit_message` `since:`, echoed in an error | Remote bodies may not carry `${` in `since:` or `vars:` |
| XML depth pre-scan ended `<?` at the first `>`: crafted file aborted alint with a stack overflow | Pre-scan lexer matches roxmltree at every skip boundary, fails closed |
| YAML depth/alias guards bypassable via flow comments and block scalars (hang / 1.6 GB) | Pre-scan ported to libyaml's token rules |
| One NUL byte disabled `no_bidi_controls` / `no_zero_width_chars` | Both scan every file; binary findings are reported, not fixed |
| `alint baseline` / `alint init` wrote outside the repo (path or symlink) | Confined writes via temp + rename, symlinks refused |

### Medium

- `alint fix` reported "applied" (exit 0) while the violation stood.
- Unreadable in-scope files passed content rules silently (now fail closed).
- Glob metacharacters in directory names (`app/[slug]`) were pasted into globs.
- `command` rules deadlocked on more than 64 KiB of output; spawn timeouts did
  not cover grandchildren holding the pipe.
- Quadratic `children_of` index build; exponential diamond `extends:` loading.
- `file_graph`: `fresh` read through escaping symlinks; `acyclic` missed cycle
  members.
- Four content rules skipped non-UTF-8 files.
- `.alint.d/` drop-ins reset unset top-level settings.
- Schema covered 15 of 26 fix ops; `extends:` entries and facts accepted
  unknown keys.
- LSP: UTF-8 vs UTF-16 columns, wiped config-file findings, stale results over
  unsaved buffers, root-only config discovery, ignored `baseline:`.
- SARIF: no `columnKind`, location-less results, unescaped `:` in URIs.
- Terminal-escape injection in `list`, `explain`, `export-agents-md`,
  `--show-baselined`.
- Release: `gh release create` not re-runnable; `vsce`/`ovsx` without
  `--skip-duplicate`; release preflight without an MSRV check; `deny.toml`-only
  PRs skipped cargo-deny; `install.sh` never tested pre-merge.

### Low

YAML merge keys and tags, numeric `equals:` semantics, `file_header` BOM
convergence, UTF-16 BOM corruption, Markdown path/link scanner gaps,
`no_case_conflicts` directory collisions, Windows reserved names, `when:`
parser gaps (`not not`, negative literals, misleading limit message),
path-less config parse errors printed twice, long-name `write_atomic`,
baseline backslash collision on Unix, duplicate same-offset inserts, log
colors, broken-pipe exit code, Windows separators in GitHub/GitLab/JUnit
output, script-injection patterns in manual workflows, CI summary ignoring
change detection, Dependabot coverage, unpinned Docker/Gradle/SSH anchors,
npm on Windows ARM, truncation-unsafe `install.sh`, CHANGELOG gaps, and stale
README / GOVERNANCE / design-doc status lines.

## Deliberate deviations

- **XML:** no big-stack parse thread; the pre-scan is fail-closed, and a
  thread per XML file is not free.
- **Glob escaping** covers the glob-typed options of nested rules (a per-kind
  table checked against the schema) and `iter.has_file`. Regex options are
  left literal, and a token substituted into a regex option is not
  regex-escaped.
- **Process-group kill** is Unix-only (via the POSIX `kill` utility, since the
  workspace forbids `unsafe`) and used only without a terminal on stdin (see
  Decisions); Windows gets the bounded output wait only.
- **Extended-config top-level settings** (`respect_gitignore`,
  `fix_size_limit`, `nested_configs`) stay ignored, now with a warning, rather
  than starting to apply once unset values stopped clobbering set ones.

## Second review round

A second, independent adversarial pass over the remediation branch (seven
reviewers: config trust, core engine, parsers, rules, CLI/LSP/output,
CI/release, and end-to-end differential runs over twelve real repositories
against `main`) reproduced about fifty further issues. Some were regressions
introduced by the first round; the rest predate it. All were fixed, each with
a regression test that fails without the fix:

- **Trust gates:** YAML tags on keys or values hid fields from every gate
  (command execution, `file_remove` promotion and env reads from a remote);
  a remote rule sharing the id of a user's spawning rule field-merged a
  `workdir:` into it; a `${` reference could be assembled from two template
  vars. Rules and templates now refuse tags, non-string keys and merge keys,
  extended configs may not contribute to spawning rules, and `workdir:` is
  confined to the repository.
- **Parsers:** the YAML alias budget counted nodes, so one large anchored
  scalar was a 3.8 GB bomb; a leading BOM shifted the YAML lexer's column and
  hid bombs in config files; roxmltree's namespace resolution is quadratic in
  the namespaces in scope. The budget is byte-weighted, the BOM is lexed as
  libyaml lexes it, flow depth is capped at 128, and XML namespaces are
  bounded.
- **Regressions from round one:** binary files produced bidi/zero-width and
  line-width false positives (seven of twelve real repositories newly failed)
  and could be rewritten by `replace`; fixability encoded in baseline keys
  broke existing baselines; process groups broke Ctrl-C and terminal prompts;
  a huge `timeout:` panicked; `not a and not b ...` hit the depth limit at 33
  terms; a quoted fence line closed a Markdown fence; an unmatched backtick
  scan went near-quadratic; `\` in directory names broke literal fast paths;
  `no_case_conflicts` dropped nested collisions; manifest dedup broke
  last-match-wins; `pair` messages used `\` on Windows.
- **CLI/LSP:** `baseline: link/../x` escaped the repository through a
  symlink; the LSP published stale results over fresh ones and ignored
  `nested_configs`; `validate-config` and `init` panicked on a closed stdout;
  several human outputs skipped terminal sanitization.
- **CI/release:** the new install.sh and supply-chain harnesses did not run
  on PRs that only touched the files they guard; the idempotency and
  script-injection harnesses checked text and had bypasses (all now
  mutation-tested); a surviving draft release stayed a draft on re-run;
  `install.sh` could die of SIGPIPE resolving `latest`.

## Decisions

The first round's open questions, and those raised by the second round, were
decided by the maintainer:

1. **Remote `ignore:`** is refused from an untrusted remote (not in
   `trusted_extends:`), like `baseline:`.
2. **Environment reads** in `when:` / `when_iter:` are refused from an
   untrusted remote: `env.*` directly, a placeholder in a remote template's
   `when`, and a var whose value comes from `{{env.X}}`. Ordinary vars stay
   readable. Nested configs keep environment access: they are files in the
   user's own repository.
3. **Binary files** in `no_bidi_controls` / `no_zero_width_chars` are scanned
   only when otherwise valid UTF-8, which keeps the NUL-evasion fix (a crafted
   source file is valid UTF-8) without false positives on media files.
4. **Process groups** are used only when stdin is not a terminal, so CI and
   the LSP get grandchild-killing timeouts while interactive runs keep Ctrl-C
   and terminal prompts.
5. **Release pointers** (`v0`, GitHub "Latest", Docker `:latest` and `:X.Y`,
   Homebrew, npm `latest`) move only when the tag is the highest release
   (or highest in its minor line, for `:X.Y`).
6. **RustSec vulnerability advisories** are blocking in CI and the release
   preflight, with waivers in `deny.toml` only.
7. **Release builds** use a pinned Rust toolchain (`RELEASE_RUST` in
   `release.yml`, enforced through `RUSTUP_TOOLCHAIN`); development and CI
   stay on `stable`.

## Known limits

- The terminal sanitizer escapes C0/C1 controls, bidi and zero-width
  characters, but not tag characters (U+E0000 block), U+00AD or U+2061-2064.
- Baselines covering `file_graph` `acyclic` or `no_case_conflicts` findings
  need regenerating (per-component and directory-level keys).
- Writes confined to the repository resolve the parent directory once; a
  directory swapped for a symlink between the check and the rename is a
  residual race (closing it needs directory-handle writes).
- `fix --dry-run` is one pass: it predicts creates that will not stick, but
  not a fix whose failure only the real run's re-check reveals.

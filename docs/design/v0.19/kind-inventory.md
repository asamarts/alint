# Kind capability inventory (snapshot at `main` b6ba88f4, 2026-10-14)

Status: snapshot, the migration map for [`kind-meta.md`](kind-meta.md) (W1). Derived from the code in `crates/alint-rules/src` and `crates/alint-core/src`, then confirmed by probing a release build with each selector (`paths`, `scope_filter`, an unsupported `fix:`, `expect_matches`) on every kind. Once W1 lands, the generated `KindMeta` section of `facts.json` supersedes this file. File references are relative to `crates/alint-rules/src/` unless prefixed; `:N` is a line in the row's source file at that commit.

Changes since the snapshot: v0.18.3 made `no_case_conflicts` and `max_files_per_directory` full-index (both keep `path_scope`), applied the scope in the structured kinds' literal-paths fast path, made blame-cache construction see nested rules, and rejected 14 kinds in nested configs (`UNCONFINABLE_KINDS`) while exempting the regex `select` of `for_each_match` and `ordered_block` from re-rooting (`REGEX_SELECT_KINDS`, both in `crates/alint-dsl/src/nested.rs`), with nested confinement now applied after template expansion and recursing into `require:` blocks, plus kind-specific re-rooting (`import_gate` `allow`, `json_schema_passes` `schema_path`, `markdown_links_resolve` `root.dir`, literal `pair` `partner`). Under `--changed` the per-file pass now matches scope and evaluates on the full context (the filtered index shares the tree's path sets); `markdown_paths_resolve` became per-file plus `requires_full_index`; `json_schema_passes` declares its schema through the new `Rule::changed_dependencies`; `file_exists`'s literal stat honours `git_tracked_only`; and a nested `require:` rule can no longer set `fix`, `git_tracked_only`, or `respect_gitignore`. The rows below are not updated; the `KindMeta` records follow the post-v0.18.3 code. The `no_submodules` row's `--changed` behaviour was judged intended (consistent with `file_absent`).

Legend: dispatch `per-file` = `as_per_file()` returns Some (file-major, engine reads bytes once); `full-index` = `requires_full_index()==true` (gets full index under `--changed`); `rule-major scoped` = neither, but `Rule::path_scope()` is Some (filtered index under `--changed`, skip-by-intersection); `single-shot unscoped` = none of the three (always evaluated, filtered index under `--changed`). No kind's `as_per_file`/`requires_full_index` depends on options. Engine-wide: every kind may be gated by `when:`; every kind's fixers get the per-rule `allow_out_of_root` policy at fix time; `{{env.X}}` interpolation happens at DSL load for any field.

Probe columns (paths / scope_filter / fix / expect_matches) were verified for every kind: a selector marked **silently ignored** loads and runs without error and has no effect.
